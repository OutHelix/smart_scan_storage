## 1. Подготовка данных

### 1.1. Загрузка и предобработка данных

В соответствии со стратегией валидации, разработанной в лабораторной работе №2, подготовка данных выполнялась с учётом критического требования — предотвращения утечек между страницами одного документа. Для этого на этапе загрузки каждому документу был присвоен уникальный идентификатор `document_id`, который сохранялся на протяжении всего пайплайна обработки.

**Источники данных:**
- **RVL-CDIP-small-200** — уменьшенная версия датасета RVL-CDIP, содержащая 200 000 изображений, разделённых на 16 классов документов. Каждый файл в этом датасете представляет собой отдельный документ, что технически упрощает разбиение.
- **FUNSD** — 199 отсканированных форм с детальными аннотациями на уровне слов и bounding boxes. Для обучения OCR из датасета были извлечены word-level кропы (вырезанные изображения отдельных слов) вместе с соответствующими текстовыми метками.

**Предобработка изображений:**

Для классификации документов использовались следующие трансформации:
- Изменение размера до 224×224 пикселей
- Случайный поворот на 3 градуса (только для обучающей выборки)
- Преобразование в тензор
- Нормализация с параметрами ImageNet (mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])

Для OCR из датасета FUNSD выполнялось извлечение word-level кропов:
- Из аннотаций извлекались bounding boxes для каждого слова
- Кропы расширялись на `crop_pad=2` пикселя для добавления контекста
- Фильтровались слова длиной менее `min_word_len=1` символа
- Всего было извлечено 21 963 обучающих примера (после ограничения 2000 для ускорения) и 7 282 тестовых примера

Все параметры предобработки вычислялись исключительно на обучающей выборке и фиксировались для применения к валидационной и тестовой выборкам.

### 1.2. Разделение на обучающую, валидационную и тестовую выборки

Разделение данных выполнялось с обязательным соблюдением принципа группировки по документам для предотвращения утечек.

**Для классификации (RVL-CDIP-small-200):**
- Общая выборка: 16 классов документов
- Размеры выборок: Train = 10 184, Val = 1 280, Test = 2 560
- Разбиение выполнено с использованием стратифицированного подхода для сохранения пропорций классов

**Для OCR (FUNSD):**
- Использовалась стандартная структура FUNSD с разделением на `training_data` и `testing_data`
- Из обучающей части дополнительно выделена валидационная выборка (10% документов) с группировкой по `doc_id`
- Итоговое распределение: Train = 2 000 примеров, Val = 3 156 примеров, Test = 7 282 примера

```python
# Пример группировки по документам для OCR
def split_grouped_samples(samples, val_size=0.1, seed=42):
    doc_ids = sorted({s["doc_id"] for s in samples})
    train_docs, val_docs = train_test_split(doc_ids, test_size=val_size, random_state=seed)
    train = [s for s in samples if s["doc_id"] in set(train_docs)]
    val = [s for s in samples if s["doc_id"] in set(val_docs)]
    return train, val
```

## 2. Выбор и реализация baseline-модели

### 2.1. Baseline для классификации документов

В качестве baseline-модели для задачи классификации документов был выбран ResNet18 с замороженным backbone (обучалась только голова классификатора). Выбор обоснован следующими соображениями:

- **Быстрое обучение** — обучение только головы классификатора занимает около 10 эпох и позволяет быстро получить нижнюю границу качества
- **Использование предобученных весов** — ResNet18 предобучен на ImageNet, что даёт хорошее начальное представление о визуальных признаках
- **Простота реализации** — архитектура хорошо изучена и проста в настройке

**Реализация:**
```python
class DocumentClassifier(nn.Module):
    def __init__(self, num_classes: int, freeze_backbone: bool = True):
        super().__init__()
        backbone = torchvision.models.resnet18(weights=ResNet18_Weights.DEFAULT)
        in_features = backbone.fc.in_features
        backbone.fc = nn.Identity()
        
        self.backbone = backbone
        self.head = nn.Linear(in_features, num_classes)
        
        if freeze_backbone:
            for param in self.backbone.parameters():
                param.requires_grad = False
    
    def forward(self, x):
        features = self.backbone(x)
        return self.head(features)
```

**Результаты на валидационной выборке:**
| Метрика | Значение |
|---------|----------|
| Accuracy | 0.488 |
| Macro Precision | 0.487 |
| Macro Recall | 0.488 |
| Macro F1 | 0.480 |

Полученные результаты значительно выше случайного угадывания (1/16 = 0.0625), что подтверждает наличие визуального сигнала в данных. Однако метрики далеки от идеала, что оставляет пространство для улучшений.

### 2.2. Baseline для OCR (распознавание текста)

Для OCR в качестве baseline была выбрана модель Tesseract. Tesseract является зрелым open-source решением, которое:

- **Не требует GPU** — может работать на CPU
- **Поддерживает множество языков** — включая английский, используемый в FUNSD
- **Имеет простое API** — интеграция через pytesseract занимает несколько строк кода

**Реализация:**
```python
def evaluate_tesseract_ocr(samples, lang="eng"):
    preds = []
    refs = []
    for sample in samples:
        image = sample["image"]
        ref = normalize_text(sample["text"])
        pred = pytesseract.image_to_string(image, lang=lang)
        pred = normalize_text(pred)
        preds.append(pred)
        refs.append(ref)
    return compute_metrics(preds, refs)
```

**Результаты на валидационной выборке FUNSD:**
| Метрика | Значение |
|---------|----------|
| CER | 0.124 |
| WER | 0.258 |
| Exact Match | 0.614 |

CER 12.4% означает, что в среднем 12 символов из 100 распознаны неверно. Это превышает целевой порог 5% для полностью автоматической обработки, что подтверждает необходимость использования более совершенной OCR-модели.

## 5. Анализ ошибок

### 5.1. Анализ ошибок классификации

**Матрица ошибок (нормализованная по строкам):**

Анализ confusion matrix выявил следующие устойчивые паттерны ошибок:

| Верный класс | Ошибочный класс | Причина |
|--------------|-----------------|---------|
| letter | memo | Структурное сходство: оба типа имеют обращение, основную часть и подпись |
| form | questionnaire | Похожая структура полей ввода |
| invoice | form | Счета часто содержат таблицы, похожие на формы |
| scientific_publication | scientific_report | Близкие по содержанию и структуре |

**Типология ошибок классификации:**

1. **Визуально схожие классы** — документы, имеющие похожую структуру расположения текста и элементов

2. **Ошибки на изображениях низкого качества** — размытые изображения, низкое разрешение, шум

3. **Сложные классы с неоднозначной структурой** — документы, которые сложно однозначно отнести к одному классу

4. **Ошибки на редких классах** — недостаточное количество примеров в обучающей выборке

### 5.2. Анализ ошибок OCR

**Типология ошибок OCR (на основе анализа 1000 примеров с CER > 0):**

| Тип ошибки | Доля | Пример | Причина |
|------------|------|--------|---------|
| Цифровые ошибки | 35% | "0" ↔ "O", "1" ↔ "l", "3" ↔ "8" | Похожесть символов, низкое разрешение |
| Ошибки на границах слов | 25% | "invoi ce" → "invoice" | Неправильное определение пробелов |
| Артефакты изображения | 20% | Заливки, шум, печати | Дефекты сканирования |
| Нестандартные шрифты | 10% | Декоративные шрифты | Отсутствие в обучающей выборке |
| Специальные символы | 10% | "№", "©", "®" | Редкие символы |

**Примеры критических ошибок:**

*Пример 1: Ошибка в распознавании цифр*
```
Оригинал: "1000"
Tesseract: "1O00"
TrOCR: "1000"
```
TrOCR успешно справился с задачей благодаря контекстному пониманию.

*Пример 2: Ошибка на границе слова*
```
Оригинал: "invoice"
Tesseract: "invoi ce"
TrOCR: "invoice"
```
Трансформерная архитектура лучше учитывает контекст и корректно объединяет части слова.

|---------|-----|-----|-------------|

**Нефункциональные характеристики:**
| Характеристика | Значение |

- Fine-tuned TrOCR снижает CER с 12.4% до 6.9% по сравнению с Tesseract на валидации

- Модель успешно справляется с различными типами документов из FUNSD

### 6.3. Инференс на целых страницах

Для практического использования был реализован пайплайн инференса, обрабатывающий целые страницы документов из папки `samples`:

1. **Детекция текстовых блоков** — с помощью Tesseract определяются координаты всех текстовых областей на странице
2. **Вырезание кропов** — каждый обнаруженный блок вырезается с небольшим отступом (pad=4)
3. **Распознавание** — fine-tuned TrOCR распознаёт текст на каждом кропе
4. **Сборка результата** — распознанные слова собираются в строки и абзацы на основе информации о блоках из Tesseract

Такой подход решает проблему, когда TrOCR, получая целую страницу, начинал «зацикливаться» на коротких фрагментах и выдавать мусор.

**Результаты инференса на образцах:**
- Классификация выполняется с высокой уверенностью (0.85–0.99)
- Распознанный текст сохраняется в структурированном виде
- Результаты сохраняются в CSV для дальнейшего анализа
